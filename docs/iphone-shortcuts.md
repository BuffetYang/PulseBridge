# iPhone 快捷指令配置指南

PulseBridge 使用 iPhone 自带的「快捷指令」读取 HealthKit 数据，并通过同一 Wi-Fi
POST 到 Windows 电脑。全程免费，不需要第三方 App、不需要 Apple 开发者账号。

> 电脑端程序会实时显示你的局域网地址与 Token。本文中的
> `http://192.168.1.100:8765` 与 `YOUR_TOKEN` 请替换为「同步与配对」页显示的实际值。
> 也可以在程序内点击「打开 iPhone 配置指南」，指南会自动填好这两项。

---

## 0. 准备

1. iPhone 与 Windows 电脑连接**同一个 Wi-Fi**（不要使用访客网络）。
2. 电脑上启动 PulseBridge，允许 Windows 防火墙的**专用网络**访问。
3. 用 iPhone Safari 打开 `http://<电脑IP>:8765`，看到「接收服务运行中」即连通。
   - 程序默认会选择默认路由 / Wi-Fi 网卡的地址。如果电脑装了 VMware、VirtualBox、
     Hyper-V，地址列表里可能出现 `192.168.x.1` 这样的虚拟网卡地址，手机无法访问；
     请在程序「同步与配对 → 网络地址」中切换到 Wi-Fi 地址。
4. 如果打不开：
   - **先点「同步与配对」页的「修复防火墙」**。Windows 10/11 常把 Wi-Fi 识别为
     「公用网络」，公用网络默认拦截入站连接，而且不会弹任何提示。点按钮后同意 UAC
     即可添加一条仅允许本地子网访问 TCP 8765 的入站规则；也可以管理员终端执行：
     ```powershell
     netsh advfirewall firewall add rule name="PulseBridge Health Receiver" `
       dir=in action=allow protocol=TCP localport=8765 profile=any remoteip=localsubnet
     ```
   - 检查是否同一网段（IP 前三段相同）；
   - 路由器是否开启了「AP 隔离 / 访客隔离」；
   - 电脑是否休眠（休眠时收不到，唤醒后下次同步会补齐）；
   - 确认使用的是 Wi-Fi 网卡地址，而不是 VMware / VirtualBox 虚拟网卡地址。

> **Safari 提示「无法与服务器建立安全的连接」？**
> 这是 iOS 18.2+ Safari 的 HTTPS-First 功能把 `http://` 自动升级成了 `https://`，
> 而 PulseBridge 是 HTTP 服务（没有 TLS 证书），所以握手失败。
> - 临时关闭：**设置 → App → Safari 浏览器 → 隐私与安全性 → 关闭「不安全连接警告」**
>   （英文为 *Not Secure Connection Warning*），然后从多任务界面彻底关闭 Safari 再重试。
> - 确认 **设置 → 隐私与安全性 → 本地网络 → Safari 浏览器** 已开启。
> - 也可以**跳过 Safari 验证**：直接在快捷指令里使用 `http://` 地址运行一次，
>   快捷指令的「获取 URL 内容」不受 Safari 的 HTTPS 升级影响。只要电脑端
>   「最近同步」出现记录，就说明链路正常。
> - 不需要为了日常同步关闭该设置；它只影响 Safari 手动验证。验证完可以重新打开。

## 0.5 不依赖 Safari 的连通性测试（推荐）

如果找不到 Safari 设置，直接跳过 Safari，用快捷指令验证：

1. 电脑端保持 PulseBridge 运行。
2. iPhone 打开「快捷指令」→ 新建，命名「PulseBridge 测试」。
3. 搜索并添加「**获取 URL 内容**」（Get Contents of URL）：
   - URL：`http://192.168.31.111:8765/api/ping`
   - 方法：GET（默认）
4. 再添加「**快速查看**」或「**显示结果**」，输入选上一步的「内容」。
5. 运行。首次会请求「本地网络」和「连接到 192.168.x.x」权限，全部允许。
6. 看到类似 `{"ok": true, "app": "PulseBridge"}` 就说明链路正常。

这一步不需要健康权限、不需要 Token，也不经过 Safari。测试通过后再按下面的步骤
创建正式的同步快捷指令。

> 如果这里也报「安全连接」错误，说明 iOS 27 的 Shortcuts 同样限制了明文 HTTP。
> 这种情况需要给 PulseBridge 增加 HTTPS（自签名本地证书）或改用其他传输方式；
> 把完整报错发我，我再按你的系统版本处理。

## 0.6 极简 POST 测试（验证 Token 与入库）

连通性没问题后，用一条硬编码样本验证 POST、Token 和数据库。
**不需要添加日期动作**：极简格式里 `start` / `end` 可以省略，服务端会用接收时间。

1. 添加「**获取 URL 内容**」：
   - URL：`http://192.168.31.111:8765/api/ingest`
   - 方法：**POST**
   - 请求头：`X-PulseBridge-Token` = 程序里复制的 Token
   - 请求体：**JSON**，添加字段：

     | 字段 | 类型 | 值 |
     | --- | --- | --- |
     | `device` | 文本 | `iPhone` |
     | `type` | 文本 | `heart_rate` |
     | `value` | 数字 | `72` |
     | `unit` | 文本 | `count/min` |
     | `source` | 文本 | `快捷指令测试` |

2. 运行。电脑端「最近同步」出现「+1 样本」，仪表盘出现当前时间的心率点，
   说明 POST、Token、入库全部正常。

这是单条样本的极简格式，适合先跑通；正式同步时再按第 2 步用循环批量发送，
起止时间来自健康样本本身。

> 「无法在获取 URL 内容上方加动作」也没关系：iOS 27 的添加按钮默认把新动作
> 追加到末尾，需要拖动才能调整顺序；本测试不需要日期动作，因此不用调整。

## 1. 新建快捷指令

打开「快捷指令」App → 右上角 **+** → 重命名为「同步健康数据到 PulseBridge」。

建议先只做 4 个指标：**心率、步数、活动能量、睡眠**，跑通后再扩展。

## 2. 采集健康样本

每个指标都需要一套「查找 → 重复 → 详细信息 → 词典 → 添加到变量」结构，
所有词典都追加到同一个变量 `样本` 里。

以**心率**为例：

1. 添加「**查找健康样本**」
   - 类型：心率
   - 筛选：开始日期 **在最近 2 天**
   - 排序：开始日期，最新在前
   - 限制：1000
2. 添加「**重复**」，重复「健康样本」
3. 在循环内添加「**获取健康样本详细信息**」，样本选「重复项目」
4. 在循环内添加「**词典**」，键值如下（值从「详细信息」中选择）：

   | 键 | 值 |
   | --- | --- |
   | `type` | 文本 `heart_rate` |
   | `start` | 详细信息 → 开始日期 |
   | `end` | 详细信息 → 结束日期 |
   | `value` | 详细信息 → 数值 |
   | `unit` | 详细信息 → 单位 |
   | `source` | 详细信息 → 来源 |

5. 在循环内添加「**添加到变量**」
   - 变量：`样本`
   - 值：上一步的词典
6. 循环外添加「**结束重复**」

然后对以下类型重复第 1–6 步，只需修改「查找健康样本」的类型和词典里的 `type`：

| 指标 | `type` |
| --- | --- |
| 步数 | `steps` |
| 活动能量 | `active_energy` |
| 睡眠 | `sleep_analysis` |
| 静息心率 | `resting_heart_rate` |
| 心率变异性 | `hrv` |
| 血氧 | `oxygen_saturation` |
| 呼吸频率 | `respiratory_rate` |
| 体重 | `body_mass` |

**睡眠特别说明**：类型选「睡眠」，最近 2 天。详细信息里的「值」是
`Core / Deep / REM / 清醒 / 核心 / 深度` 之类的文本，直接作为 `value` 发送即可。
PulseBridge 会自动识别阶段，并用起止时间计算每个阶段的时长。

> **为什么每次拉最近 2 天？** 这样即使某次自动化没触发，下次也能补上；
> 服务端会按样本 UUID（或内容指纹）去重，不会重复存储。

## 3. 采集运动记录（推荐）

1. 添加「**查找体能训练**」
   - 筛选：开始日期 **在最近 2 天**
2. 添加「**重复**」，重复「体能训练」
3. 循环内添加「**获取体能训练的详细信息**」，属性选择：类型、开始日期、结束日期、持续时间
4. 循环内添加「**词典**」：

   | 键 | 值 |
   | --- | --- |
   | `type` | 详细信息 → 类型 |
   | `start` | 详细信息 → 开始日期 |
   | `end` | 详细信息 → 结束日期 |
   | `duration_s` | 详细信息 → 持续时间 |
   | `source` | 文本 `Apple Watch` |

   可选：`distance_m`（米）、`energy_kcal`、`avg_hr`、`max_hr`。
   如果详细信息里的距离单位不是米，可先用「转换单位」动作转成米再填入。
5. 循环内「**添加到变量**」，变量名 `运动`；循环外「结束重复」

## 4. 发送到电脑

1. 添加「**词典**」，作为最终请求体：

   | 键 | 值 |
   | --- | --- |
   | `device` | 文本 `iPhone` |
   | `samples` | 变量 `样本` |
   | `workouts` | 变量 `运动` |

2. 添加「**获取 URL 内容**」：
   - URL：`http://<电脑IP>:8765/api/ingest`
   - 方法：**POST**
   - 请求头：`X-PulseBridge-Token` = 你的 Token
   - 请求体：**JSON** → 选上一步的词典
3. 点击运行。电脑端「同步与配对 → 最近同步」会出现一条记录，仪表盘开始有数据。

### 请求体格式（参考）

```json
{
  "device": "iPhone",
  "samples": [
    {
      "type": "heart_rate",
      "start": "2026-11-12T08:00:00+08:00",
      "end": "2026-11-12T08:01:00+08:00",
      "value": 72,
      "unit": "count/min",
      "source": "Apple Watch"
    },
    {
      "type": "sleep_analysis",
      "start": "2026-11-12T01:00:00+08:00",
      "end": "2026-11-12T02:30:00+08:00",
      "value": "Core",
      "source": "Apple Watch"
    }
  ],
  "workouts": [
    {
      "type": "running",
      "start": "2026-11-12T07:00:00+08:00",
      "end": "2026-11-12T07:30:00+08:00",
      "duration_s": 1800,
      "distance_m": 5020,
      "energy_kcal": 320,
      "avg_hr": 152
    }
  ]
}
```

时间支持 ISO 8601（含时区）、Unix 秒 / 毫秒；`value` 支持数字或文本（睡眠阶段）。

## 5. 自动化（每小时同步）

**iOS 的「时间」自动化只支持每天 / 每周 / 每月，没有「每小时」间隔触发器。**
推荐下面的组合：

- **定点同步**：快捷指令 → 自动化 → 新建 → 「时间」→ 08:00 → 每天 → 立即运行 →
  选择这条快捷指令。需要严格每小时就创建 24 条；更实际的是创建白天 8:00–23:00 的
  16 条，或只建早 / 中 / 晚 / 睡前 4 条。
- **事件触发**（更省事）：再建两条自动化：
  - 「连接家庭 Wi-Fi 时」
  - 「开始充电时」
  都指向同一条快捷指令。拿起手机或回家充电时自动补数据。
- 可以把快捷指令加到主屏幕，随时手动运行。

首次运行时 iOS 会请求：
- **本地网络**权限：必须允许，否则无法访问电脑；
- **健康**权限：设置 → 隐私与安全性 → 健康 → 快捷指令 → 打开所需类别。

> 后台自动化在 iOS 上不是严格实时的，系统可能延迟执行。因为每次都拉取最近 2 天并去重，
> 延迟只影响「数据出现的时间」，不会造成数据缺失。

## 6. 电脑端手动验证

PowerShell（替换地址和 Token）：

```powershell
curl.exe -X POST "http://192.168.1.100:8765/api/ingest" `
  -H "Content-Type: application/json" `
  -H "X-PulseBridge-Token: YOUR_TOKEN" `
  -d '{\"device\":\"iPhone\",\"samples\":[{\"type\":\"heart_rate\",\"start\":\"2026-11-12T08:00:00+08:00\",\"end\":\"2026-11-12T08:01:00+08:00\",\"value\":72,\"source\":\"Apple Watch\"}],\"workouts\":[]}'
```

返回 `{"ok": true, ...}` 即服务正常。也可以直接访问
`http://127.0.0.1:8765/api/ping` 检查本机服务。

## 7. 排错

| 现象 | 原因 / 解决 |
| --- | --- |
| 401 `token 无效` | 快捷指令中的 Token 与「同步与配对」页不一致；重新生成 Token 后必须同时更新快捷指令 |
| 无法连接 | 不在同一 Wi-Fi、电脑休眠、防火墙拦截（点击「修复防火墙」）、路由器 AP 隔离、IP 已变化或选到了 VMware/VirtualBox 虚拟网卡地址 |
| Safari 提示「无法建立安全连接」 | iOS 18.2+ Safari 把 http 升级成了 https；关闭 Safari「隐私与安全性 → 不安全连接警告」，或跳过 Safari 直接用快捷指令测试 |
| 运行成功但没数据 | 健康权限未开；筛选时间范围不对；「查找健康样本」限制太小 |
| 步数偏少 | 多来源时程序按「单来源合计的最大值」统计，避免 iPhone + Watch 重复计数；确认 Apple Watch 已同步到健康 App |
| 睡眠没有深睡/REM | 需要 Apple Watch 开启「睡眠跟踪」；iPhone 单独记录通常只有「在床上 / 睡眠」 |
| 运动没有距离/消耗 | 快捷指令的运动词典里需要额外添加 `distance_m` / `energy_kcal` 键 |
| 电脑重启后手机连不上 | 局域网 IP 可能变化；在「同步与配对」查看新地址，或在路由器中给电脑固定 IP |

## 8. 安全说明

- 服务只在局域网监听，Token 用于写入鉴权，请勿将端口映射到公网。
- 数据仅保存在本机 `%APPDATA%\PulseBridge\pulsebridge.db`。
- 导出 JSON 含完整健康数据，分享前请脱敏。
